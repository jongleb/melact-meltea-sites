Benchmarks

Within ×1.2 of hand-written JavaScript.

A local reproduction of the keyed CPU, memory and size tests of js-framework-benchmark, in headless Chrome, for Meltea against hand-written vanilla JS and React 18 with hooks. The ratios move by about 0.1 between runs.

Swapping two rows of 1,000 is two DOM moves in Meltea; React moves 998. A list re-renders only the rows whose item changed.

Method

Measured the way js-framework-benchmark measures.

The four apps render the same markup and share one small inline stylesheet; the harness downloads nothing. Vanilla is hand-written keyed DOM code in the style of the benchmark's vanillajs-keyed; React is 18.3 with hooks, like the benchmark's react-hooks.
  • Every sample is a fresh tab: load, the benchmark's warmups for that operation, then one measured click, sent as real mouse input.
  • The measured click is traced. The time is the renderer main thread's busy time from the start of the click dispatch to the end of the first Paint and its Commit after it.
  • CPU slowdown as in the benchmark: 4× for partial update, select, swap and clear, 2× for remove.
  • After every measured click the page is checked: row count, every id in order, every label, the markup of every row, and which rows have class="danger". A fast but wrong result is reported, not counted silently.
  • Memory: two forced garbage collections, then the heap usage after creating 1,000 rows.
  • Size: the gzip (-9) size of all JS in the production bundle.
