Migrate in two lines

Change the libraries. Keep the components.

Melact keeps reason-react's surface (React.useState, useEffect, useContext, ReactDOM.Client, React.Event, ReasonReactRouter …) and replaces what is underneath it.

1your dune file

dune
- (libraries reason-react)
+ (libraries melact)
- (preprocess (pps reason-react-ppx))
+ (preprocess (pps melact-ppx))

2your components stay as they are

counter.mlx
let[@react.component] make ~initial () =
  let count, setCount = React.useState (fun () -> initial) in
  let tone = if count < 0 then "negative" else "" in
  <div className="counter">
    <button onClick=(fun _ -> setCount (fun n -> n - 1))>(React.string "-")</button>
    <output className=tone>(React.int count)</output>
    <button onClick=(fun _ -> setCount (fun n -> n + 1))>(React.string "+")</button>
    <button onClick=(fun _ -> setCount (fun _ -> initial)) disabled=(count = initial)>
      (React.string "reset")
    </button>
  </div>

Why Melact

The same component model, compiled.

  • 01

    No virtual DOM

    A render does not build a tree of elements to diff. It builds one array: the values of the holes in a template. Everything static is parsed once, at module load, and cloned.

  • 02

    Exact change detection

    “Did this hole change” is ===. An unchanged reference is an unchanged value, so a physically equal child list or lazy argument skips its whole subtree.

  • 03

    Updates start where state changed

    A setState re-renders its own component, not the root. Children with physically unchanged props are skipped without memo.

  • 04

    Few DOM moves for lists

    Keyed lists keep their common prefix and suffix, and the longest increasing run of old positions. Swapping two of 1,000 rows is 2 insertBefore calls.

  • 05

    One listener per event type

    Bubbling events are delegated to document. A handler is a property on its element, so a new closure each render costs one property write.

  • 06

    Still reason-react

    Same JSX in mlx, Reason or OCaml [@JSX], and the same hooks with the same signatures. Pure-OCaml reason-react code is the compatibility target.

Server rendering

HTML in React's format, hydrated by compiled code.

ReactDOMServer.renderToString writes HTML in the format of React's own renderToString, with no markers, so a Melact app can also render on a native OCaml server with server-reason-react. ReactDOM.Client.hydrateRoot takes that HTML over in document order, and clicks and typing made before the code arrives are delivered in order.
